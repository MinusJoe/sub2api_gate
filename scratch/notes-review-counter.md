## 1. 三路互相印证 vs 矛盾点

### 1.1 强互相印证（三路收敛，可信度高）

| 事实 | 角 A | 角 B | 角 C |
|---|---|---|---|
| turn-state 是服务端加密票据、客户端不可伪造 | Fernet 1+8+16+528+32=585B，HMAC 密钥在服务端（观察） | 官方 PR #9332 契约（实锤） | 票不可伪造（Fernet 585B） |
| turn-state 是 per-turn / per-account，跨账号共享违反契约 | 跨账号回放=矛盾信号（网关 guard 侧） | PR #9332「跨回合必须清空、与铸造账号绑定」 | per-turn sticky token |
| 降智 = 服务端路由，任何本地票无法解除 | safety-buffering 头 + 流内换模（209/347 实锤） | A2：Tibo 承认 Astra 自身质量缺陷（09-12） | 降智=上游后端强制（CLIProxyAPI #5941） |
| 本机无封号/身份异常实锤 | 风控词表 48579 行日志全 0 触发 | thread_history error_json 无封号痕迹 | — |
| 票长 292/332→780（09-22），旧校验失效 | 780=33 块 Fernet | B2（官方 issue #8104 + linux.do 实测） | — |

### 1.2 关键补充（互相补全，非矛盾）

1. **角 C 的「政策级」事实是角 A/B 的盲区**：OpenAI 2026-10-20/21 公告，**2026-11-20 起「模型路由器 / AI 网关」这类中转服务须先经 OpenAI 审核批准**。sub4api 是「AI 网关」→ 这是比任何二进制反制都更顶层的收口。角 A 的「反制机制清单」与角 B 的「执法时间线」都未覆盖这条，三者拼起来才完整。
2. **角 B 的「降智归因反向证据」补充角 A**：角 A 说「降智=服务端路由决定」；角 B A2 给出官方 postmortem「badly configured engines → measured quality degradation for long tail」（09-12）→ 说明「降智观感」里有相当一部分是**官方引擎 bug 而非账号被标记**。两者兼容：降智是服务端路由，路由原因可能来自（a）容量管理、（b）账号分类、（c）引擎缺陷——不能都归因于「被打票/被标记」。
3. **「未实锤封号」≠「安全」**（角 B 自陈，非矛盾）：本机无封号（观察）+ 社区「打票封号」传闻互相矛盾（低可信）+ 官方风控是**静默标记**（未必显式 error_json）→ 结论是「尚未处置」，不能反证安全。

### 1.3 无实质矛盾，仅两处「诚实标注的未知」

1. 角 C「API key 直连无静默换模」是**高置信推断（API 端零实测=未知）**，角 A「降智=服务端路由」是**机制观察**——二者不冲突，只是角 C 更谨慎。
2. 角 A 上一轮曾建议「HTTP 首请求形状对齐打票」，与角 B/C 的「共享=欺诈红线」「无安全伪造通道」**方向冲突**——本轮综合后**撤销该建议**：形状对齐打票本质仍是「模拟官方客户端去获取/回带 per-turn 票据」，在官方已明示「订阅转 API 共享 = fraud-flag」+ turn-state 契约下，不能作为「安全」路径推荐（见 §2）。

## 2. 综合三路：sub4api「安全稳定替代方案」最终排序（1~3）

| 排序 | 方案 | 合规度 | 稳定性 | 成本 | 风险 | 一句话理由 |
|---|---|---|---|---|---|---|
| **1** | **API key 直连**（`api.openai.com/v1/responses`，BYOK 或代持按 token 计价） | ★★★★★ | ★★★★★ | 中（按量） | 极低 | 唯一「完全合规 + 稳定」线路：不踩 OAuth 后端（turn-state/attestation/routing-hint/cookie 全不适用），无静默换模，同时是对冲 11-20 政策的合规资产。 |
| **2** | **官方 Partner Network / Marketplace** | ★★★★★ | ★★★★☆ | 高（企业级） | 低 | 若目标是对外「转售/分发 Codex/API」，这是唯一官方背书通道；与 P0 互补（P0 自用/代持，P2 商业化）。 |
| **3** | **合规账号运维**（真实号 + `response.created.response.model`==请求模型 的 served-model 检测 + 冷却/养号，**不伪造、不共享**） | ★★★☆☆ | ★★★☆☆ | 中 | 中 | 「保留 ChatGPT OAuth 体验」前提下最稳组合：可观测、不伪造、灰区外长期站住；Fast/priority 提速 + 时区治理并入此档，A/B 自测传输（勿照抄旧结论）。 |

> 明确排除（三路一致）：**「打票/共享票注入」不再作为任何推荐**——角 A 证其不可伪造且 per-turn/per-account、角 B 证共享=fraud-flag、角 C 证无安全伪造通道。若保留打票能力，仅可作「同账号同回合回传 + 默认关闭 + 票长自适应」的非共享、非对外分发形态，且不承诺任何「防降智/稳定」。

## 3. 官方应对「打票/共享」：实锤 / 可绕过 / 未知 三分

### 3.1 已实锤、不可绕过

| 机制 | 证据 | 结论 |
|---|---|---|
| turn-state 密码学不可伪造 | Fernet（服务端 AES-128-CBC + HMAC-SHA256），585B，内嵌铸造时间戳 | **不可绕过**（只能原样回带；伪造在密码学上不可行） |
| turn-state per-turn / per-account 契约 | 官方 PR #9332（跨回合清空、与铸造账号绑定） | **不可绕过**（跨账号/跨回合共享=契约违反，会被上报为限流绕过） |
| 共享/分发 = fraud-flag | Tibo 08-21 官方点名 sub2api「not supported + 反欺诈标记」 | **不可绕过**（红线官方明示，早于打票功能） |
| 票长 292/332→780（09-22） | 官方 issue #8104 + 本机 142 条恒 780 | **不可绕过**（旧长度校验失效；需 Fernet 信封自适应解析） |
| 版本门槛 / UA-originator 配套 | issue #3901（version<0.144.0 上游 404） | **不可绕过**（硬门槛） |

### 3.2 可观测、可绕过（或可绕开）

| 机制 | 可观测性 | 「绕过/绕开」方式 |
|---|---|---|
| 降智/换模 | `x-codex-safety-buffering-*` 头（本机 209/347 实锤）+ 流内 `response.created.response.model`（需读 SSE/WS body） | **可绕开**（走 API key 直连，不在该路由下）；**不可伪造解除** |
| 账号分类/额度 | `x-codex-active-limit/credits-*/rate-limit-reached-type`（响应头，只读） | 服务端判定，客户端**不可伪造高档位** |
| 边缘 cookie | `__cf_bm`(/responses 15/347)、`__oailb`(/models 128) | 可观测；跨 IP 复用会与边缘粘性矛盾（露馅点） |
| 身份/行为指纹 | turn-metadata 32 字段 + 头体一致 + UA/originator/version | 可「更像官方客户端」，但**只提高被当作真客户端的概率，不产生稳定性** |

### 3.3 未知（本机不可判定，需服务端/抓包证据）

| 项 | 状态 |
|---|---|
| `x-oai-attestation` 是否被服务端**强制校验**、精确算法（Ed25519/P-256、签什么 claims） | **未知**；仅知「生成需要 app-server（`attestation/generate` + `device_key_bindings`），CLI/exec 无 app-server 无法生成」 |
| 官方是否会对「打票/共享」**实锤封号** | **未知**（本机无封号、社区传闻矛盾；官方风控是静默标记） |
| 风控词表（cyber/bio/misalignment/too_many_denials）的触发条件 | **未知**（本机 48579 行日志全 0 触发） |
| 11-20 政策「网关过审」的具体门槛/流程 | **未知**（官方仅方向性表述） |

## 4. 一句话收束（角 A 综合）

**三路一致指向同一结论：官方对「打票/共享」的应对 = 「密码学不可伪造的 per-turn 票据」 + 「共享即欺诈的官方红线」 + 「静默风控标记」 + 「11-20 网关过审政策收口」；其中票据不可伪造、共享=欺诈、票长变更、版本门槛是「实锤不可绕过」，而「是否实锤封号 / attestation 是否强制校验 / 风控触发条件」仍是未知。安全稳定的终点是官方计费（API key / Partner），「稳定」的终点是可观测的账号运维；两者之间没有「伪造出来的 VIP」。**
