# 角 2 集体评审结论（agent2-identity）

读齐三份笔记后评审。三份笔记**从三个独立角度收敛到同一结论**，无实质矛盾；分歧只在「修什么优先级最高」，不在「票是什么」。

---

## 1) 三角有无实质矛盾？采信 / 异议

**无实质矛盾**。三角一致钉死：

- 票 = **per-turn 粘性路由票据**（非 VIP/防降智凭证）：角1（HTTP 响应头拿、WS 握手回带）、角2（Fernet 加密能力令牌、跨账号=矛盾信号）、角3（per-turn、跨回合/跨账号必须清空）三方互证。
- 票长 292/332 → **780**（2026-09-22 起），三者口径一致；角2 补充 Fernet 数学：780=33 密文块合法，292 无填充 base64url 下不自洽（削弱 292 可信度）。
- `__oailb` 只在 `/models`、`/responses` 上只有 `__cf_bm`（cookie-only 假票），角1/角3/client-evidence 一致。

**采信**：
- 角1「拿票必须走 WS」**纠正上一轮**为「HTTP 响应头拿、WS 回带」——采信，且与我角2 的「回带仅 WS」措辞不冲突（我本就说的是回带侧）。
- 角3「降智权威判据 = 请求模型 vs 流内 `response.created.response.model` / `openai-model`，票治不了降智」——**采信，且这是三角里层级最高的 reframe**。

**仍异议（两点，非矛盾）**：
1. 角1 把 `OpenAI-Beta: responses=experimental` 判为「硬错误」是[观察]成立的（真实客户端全二进制 0 次、HTTP 不发），但它是否就是「拿不到票的**直接因果**」仍是[推断]——服务端可能忽略未知 beta 头而非因此拒铸票。需 A/B 坐实。
2. 角2 我自己的「获取错配」措辞偏弱：应明确为「拿票走 HTTP（响应头）、回带走 WS」，避免读者误读成「拿票也要 WS」。

## 2) 我最推荐方案：坚持 / 降级 / 修正？

**修正 + 部分降级**。

我原最推荐「放弃全站共享、改同账号同回合 WS 续传透传」——读完后判定：
- **方向对但层级错**：它被角3 印证为官方契约正解（角3 次选#1，B1/B2），是「合规路由连续性」手段，但**不是防降智手段**。故**降级为次选**，不能当最推荐。
- **缺一半**：我只讲了「回带/注入走 WS」，没强调「**拿票走 HTTP 响应头**（角1 的纠正）+ 探针形状对齐」这半边。
- 修正后的定位：capture 侧按角1 修 HTTP 探针形状；echo 侧按角2/角3 per-turn/per-account 回传 + 跨账号剥离。两者合起来才是「票」这条线的正确姿势。

**新的最推荐** = 角3 的「降智检测改判据 + 账号冷却/换号」，因为只有它真正作用于原始目标「防降智」，票线无论怎么修都到不了这个目标。

---

## 3) 给 sub4api 的「合理解决方案」排序

1. **（最推荐）降智判据换成「流内实际模型」**：网关读 SSE/WS 的 `response.created.response.model`（及 `response.metadata.openai-model`）与请求模型比对 + 记录 `x-codex-safety-buffering-*`，命中即标记/冷却/切号。可行性高（已有骨架）、风险低-中（纯观测+运维）、成本中（扩展 SSE/WS body 解析）。——唯一作用于「质量」。

2. **（次选）修探针形状 + per-turn/account 票据回传（弃全站共享）**：HTTP 探针删 `OpenAI-Beta: responses=experimental`、版本对齐 0.163.0、头/body originator 同源、turn-metadata 补全 ~30 字段、加 tools；拿到的票只同账号同回合 WS 回带 + 跨账号剥离。可行性高、风险中、成本中。——「路由连续性/合规」正解，非防降智。

3. **（次选）service_tier 当「提速」运营（A/B 实测）**：`forced_service_tier=priority` 时做 HTTP/SSE vs WS 的 A/B（TPS + `x-codex-primary-used-percent` 消耗速率），ultrafast 仅 entitlement 实锤后放行，并下发 fast+fast_mode=true。可行性中（历史结论有反转）、风险低（官方功能但计费倍增需告知）、成本中。——只管速度不管降智。

**一句话收束**：票不是质量凭证、治不了降智；「真正防降智」只能靠**流内实际模型检测 + 账号运维**，票线只做「合规路由连续性」，tier 只做「提速」。
